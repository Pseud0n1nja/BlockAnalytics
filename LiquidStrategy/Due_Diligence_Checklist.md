# INSTITUTIONAL DUE DILIGENCE CHECKLIST
## Liquid Token Investment Evaluation (<$1B FDV)

---

## OVERVIEW

This comprehensive checklist provides institutional investors with a systematic framework for evaluating liquid token investments in sub-$1B FDV assets. Each section includes specific criteria, data sources, and red flags to ensure thorough analysis before investment decisions.

---

## 1. BASIC QUALIFICATION CRITERIA

### 1.1 Market Cap & Liquidity ✓/✗
- [ ] **Market Cap:** <$1B fully diluted valuation
- [ ] **Daily Volume:** >$1M average over 30 days
- [ ] **Exchange Listings:** Minimum 3 tier-1 exchanges
- [ ] **Market Depth:** >$500K liquidity within 5% slippage
- [ ] **Trading History:** >6 months of consistent trading
- [ ] **Bid-Ask Spread:** <1% on major exchanges

**Data Sources:** CoinGecko, CoinMarketCap, DeFiLlama, exchange APIs

### 1.2 Regulatory Compliance ✓/✗
- [ ] **Legal Classification:** Clear utility token status
- [ ] **Geographic Availability:** Available in target jurisdictions
- [ ] **Compliance History:** No major regulatory violations
- [ ] **AML/KYC:** Proper compliance frameworks in place
- [ ] **Tax Treatment:** Clear tax implications for institutions

**Red Flags:** SEC actions, exchange delistings, jurisdiction bans

---

## 2. FUNDAMENTAL ANALYSIS

### 2.1 Protocol Assessment ✓/✗
- [ ] **Value Proposition:** Clear and differentiated use case
- [ ] **Product-Market Fit:** Evidence of real user adoption
- [ ] **Revenue Model:** Sustainable monetization strategy
- [ ] **Token Utility:** Clear utility beyond speculation
- [ ] **Competitive Moat:** Defensible competitive advantages
- [ ] **Roadmap:** Credible development roadmap

**Scoring:** 1-10 scale for each criterion (minimum 6/10 average required)

### 2.2 Tokenomics Evaluation ✓/✗
- [ ] **Supply Schedule:** Transparent token release schedule
- [ ] **Inflation Rate:** Reasonable inflation/deflation mechanics
- [ ] **Fee Accrual:** Clear value flow to token holders
- [ ] **Governance Rights:** Meaningful governance participation
- [ ] **Staking Mechanics:** Well-designed staking incentives
- [ ] **Burn Mechanisms:** Credible token burn/buyback programs

**Red Flags:** Heavy unlock schedules, unclear value accrual, governance attacks

### 2.3 Financial Health ✓/✗
- [ ] **Treasury:** Adequate funding for 18+ months
- [ ] **Revenue Growth:** Positive revenue trajectory
- [ ] **User Growth:** Growing active user base
- [ ] **TVL/Usage:** Growing protocol usage metrics
- [ ] **Token Distribution:** Reasonable distribution among holders
- [ ] **Insider Holdings:** Acceptable team/insider allocation

**Key Metrics:** Monthly recurring revenue, user growth rates, retention metrics

---

## 3. TEAM & GOVERNANCE ANALYSIS

### 3.1 Team Assessment ✓/✗
- [ ] **Track Record:** Proven experience in relevant domains
- [ ] **Technical Competence:** Strong technical leadership
- [ ] **Previous Successes:** History of successful projects
- [ ] **Team Stability:** Low turnover, committed team members
- [ ] **Advisory Board:** High-quality advisors and investors
- [ ] **Communication:** Regular, transparent communication

**Research Sources:** LinkedIn, GitHub, previous project history, media interviews

### 3.2 Governance Structure ✓/✗
- [ ] **Decentralization:** Progressive decentralization plan
- [ ] **Voting Mechanisms:** Fair and secure governance processes
- [ ] **Proposal Process:** Clear improvement proposal system
- [ ] **Community Participation:** Active community governance
- [ ] **Transparency:** Public governance discussions and votes
- [ ] **Emergency Procedures:** Clear crisis management protocols

**Red Flags:** Centralized control, governance attacks, inactive community

---

## 4. TECHNICAL EVALUATION

### 4.1 Security Assessment ✓/✗
- [ ] **Smart Contract Audits:** Multiple audits by reputable firms
- [ ] **Bug Bounty Program:** Active bug bounty with reasonable rewards
- [ ] **Code Quality:** Clean, well-documented codebase
- [ ] **Formal Verification:** Formal verification where applicable
- [ ] **Upgrade Mechanisms:** Secure upgrade procedures
- [ ] **Historical Security:** No major exploits or vulnerabilities

**Audit Firms:** Trail of Bits, Consensys Diligence, OpenZeppelin, Quantstamp

### 4.2 Technical Architecture ✓/✗
- [ ] **Scalability:** Adequate throughput for expected usage
- [ ] **Interoperability:** Integration with major protocols
- [ ] **Composability:** Enables other projects to build on top
- [ ] **Developer Tools:** Quality developer experience
- [ ] **Documentation:** Comprehensive technical documentation
- [ ] **Open Source:** Open source codebase with active development

**Red Flags:** Closed source, poor documentation, scalability bottlenecks

- [ ] **Market Share:** Ability to capture meaningful market share

## 6. RISK ASSESSMENT

### 6.1 Technical Risks ✓/✗
- [ ] **Smart Contract Risk:** Low risk based on audits and history
- [ ] **Scalability Risk:** Technical architecture can handle growth
- [ ] **Upgrade Risk:** Smooth upgrade mechanisms without breaking changes
- [ ] **Centralization Risk:** Adequate decentralization roadmap
- [ ] **Composability Risk:** Dependencies on other protocols managed
- [ ] **Quantum Risk:** Future-proofed against quantum computing

**Risk Rating:** High/Medium/Low for each category

### 6.2 Market Risks ✓/✗
- [ ] **Liquidity Risk:** Adequate market depth for position size
- [ ] **Volatility Risk:** Acceptable volatility for risk tolerance
- [ ] **Correlation Risk:** Reasonable correlation with portfolio
- [ ] **Regulatory Risk:** Low regulatory risk in key jurisdictions
- [ ] **Competition Risk:** Sustainable competitive advantages
- [ ] **Adoption Risk:** Clear path to user adoption

### 6.3 Operational Risks ✓/✗
- [ ] **Team Risk:** Stable, committed team with succession planning
- [ ] **Funding Risk:** Adequate funding runway
- [ ] **Partnership Risk:** Strong, reliable partnerships
- [ ] **Exchange Risk:** Listed on multiple reputable exchanges
- [ ] **Custody Risk:** Secure custody solutions available
- [ ] **Insurance Risk:** Protocol insurance available where applicable

## 7. FINANCIAL MODELING

### 7.1 Valuation Analysis ✓/✗
- [ ] **DCF Model:** Discounted cash flow analysis completed
- [ ] **Comparable Analysis:** Valuation vs. comparable protocols
- [ ] **Network Value Models:** Metcalfe's law and network value analysis
- [ ] **Revenue Multiple:** P/S ratio analysis vs. peers
- [ ] **Token Velocity:** Analysis of token velocity and value capture
- [ ] **Scenario Analysis:** Bull/base/bear case modeling

**Target Metrics:** P/S <20x, P/E <30x (where applicable), reasonable NVT ratio

### 7.2 Return Projections ✓/✗
- [ ] **Time Horizon:** Clear investment timeline (12-36 months)
- [ ] **Return Expectations:** Realistic return projections
- [ ] **Risk-Adjusted Returns:** Sharpe ratio >0.3
- [ ] **Probability Weighting:** Scenario-weighted expected returns
- [ ] **Sensitivity Analysis:** Impact of key variable changes
- [ ] **Exit Strategy:** Clear profit-taking and exit plan

## 10. SCORING SUMMARY

### 10.1 Overall Assessment
**Minimum Requirements (Must Pass All):**
- [ ] Regulatory compliance confirmed
- [ ] Adequate liquidity verified
- [ ] Security assessment passed
- [ ] Team credibility confirmed
- [ ] Financial viability established

**Scoring Matrix:**
- **Excellent (8-10):** Strong buy candidate
- **Good (6-7):** Conditional buy with monitoring
- **Fair (4-5):** Hold/Watch list
- **Poor (1-3):** Do not invest

### 10.2 Decision Framework
**Investment Decision:**
- [ ] **BUY:** Score >7/10 in all critical areas
- [ ] **CONDITIONAL BUY:** Score 6-7/10 with specific conditions
- [ ] **WATCH:** Score 5-6/10, monitor for improvements
- [ ] **AVOID:** Score <5/10 or any critical red flags

**Position Sizing Based on Score:**
- 8-10/10: Full allocation (3-5% portfolio)
- 6-8/10: Reduced allocation (2-3% portfolio)
- 5-6/10: Minimal allocation (1-2% portfolio)
- <5/10: No allocation

---

## 11. RED FLAGS CHECKLIST

### 11.1 Immediate Disqualifiers ❌
- [ ] Active SEC investigation or enforcement action
- [ ] Major smart contract exploit in past 12 months
- [ ] Anonymous team with no track record
- [ ] No working product after >2 years
- [ ] Obvious Ponzi/pyramid scheme mechanics
- [ ] Illegal activity or sanctions exposure

### 11.2 Serious Concerns (Require Deep Investigation) ⚠️
- [ ] High team turnover or key departures
- [ ] Declining user base or revenue
- [ ] Multiple audit findings or security concerns
- [ ] Significant regulatory uncertainty
- [ ] Heavy token unlock schedule imminent
- [ ] Poor community sentiment or governance disputes
